# 🎾 Большой шлем и не только

Живой календарь турниров: **Большой шлем**, **Masters 1000 (ATP)** и **WTA 1000** — расписание, результаты, live-счёт и текущий рейтинг игроков. Данные обновляются автоматически через GitHub Actions.

🌐 **Сайт:** https://nikstopka.github.io/grand-slam-calendar/
📦 **Репозиторий:** https://github.com/nikstopka/grand-slam-calendar

## Возможности

- **Вкладка на каждый турнир** — Australian Open, Roland Garros, Wimbledon, US Open, Indian Wells, Miami, Мадрид, Рим, Торонто, Цинциннати, Шанхай, Париж, Доха, Дубай, Пекин и другие
- **Сетка (сетка турнира)** — каждый турнир показан в виде сетки-скобки с раундами, как на профессиональных сайтах
- **Вкладка «Рейтинг»** — актуальный мировой рейтинг ATP и WTA с очками и изменением позиции
- **Разделение по годам** — выпадающий список: прошлые сезоны с результатами и предстоящие матчи
- **Мужчины / женщины / все** — фильтр по категории внутри любого турнира
- **Основные и второстепенные матчи** — четвертьфиналы, полуфиналы и финалы отдельно от ранних раундов
- **До матча** — соперники, время, корт и обратный отсчёт
- **Во время матча** — индикатор LIVE и текущий счёт по сетам
- **После матча** — итоговый счёт и победитель
- **Фотографии игроков** — из Wikimedia Commons, с автоматической заменой на инициалы, если фото недоступно
- **Адаптивный дизайн** — работает на телефоне и компьютере

## Что вам понадобится

1. **Аккаунт GitHub** (бесплатный) — [github.com](https://github.com)
2. **API ключ Sportradar** (бесплатный, *необязательно*) — [developer.sportradar.com](https://developer.sportradar.com/)

> **Ключ Sportradar сейчас не работает.** Диагностика показала: сервер отвечает `403` с
> заглушкой «Authentication Error» даже на заведомо несуществующий путь и на другой продукт —
> то есть запросы не доходят до API, ключ отозван на уровне аккаунта. Это **не квота**

## Как всё устроено

```
┌──────────────────────────────────────────────────────────┐
│                    GitHub Actions                         │
│              (запускается каждые 6 часов)                  │
│                                                          │
│  fetch_tennis.py → Sportradar Tennis API v3 → data/      │
│         ↕ кэш (каталог, сезоны, фотографии)              │
└──────────────────────────────────────────────────────────┘
                           ↓
┌──────────────────────────────────────────────────────────┐
│                    GitHub Pages                           │
│                                                          │
│  index.html + app.js → data/index.json (список турниров)  │
│                      → data/tournaments/*.json (сетки)    │
│                      → data/rankings.json (рейтинг)       │
│                      → data/players.json (фото)           │
└──────────────────────────────────────────────────────────┘
```

Каждый турнир лежит в **отдельном файле** и подгружается только при переключении на его вкладку — поэтому страница открывается мгновенно и не весит десятки мегабайт.

## Установка

### Шаг 1. Создание репозитория

1. На GitHub нажмите **New repository**
2. Имя: `grand-slam-calendar`, видимость: **Public**
3. Нажмите **Create repository**

### Шаг 2. Загрузка файлов

Склонируйте репозиторий и скопируйте в него содержимое проекта (включая скрытые папки `.github` и `.gitignore`):

```bash
git clone https://github.com/ВАШ_НИК/grand-slam-calendar.git
cd grand-slam-calendar
# копируем содержимое проекта (Windows: robocopy путь\к\проекту . /E)
# Linux/macOS: cp -r путь/к/проекту/. .

git add .
git commit -m "Загрузка файлов проекта"
git push
```

Или загрузите файлы через веб-интерфейс (**Add file → Upload files**), перетащив **содержимое** папки проекта, а не саму папку.

### Шаг 3. API ключ Sportradar (необязательно)

1. Откройте [developer.sportradar.com](https://developer.sportradar.com/) и зарегистрируйтесь
2. Создайте приложение с продуктом **Tennis v3 (Trial)**
3. Скопируйте ключ

> Если ключа нет — ничего страшного: скрипт автоматически переключится на бесплатные
> источники. С ключом доступны точные тайминги матчей и live-обновления.

### Шаг 4. Секрет в GitHub

**Settings → Secrets and variables → Actions → New repository secret**:

- Name: `SPORTRADAR_API_KEY`
- Secret: ваш ключ

### Шаг 5. GitHub Pages

**Settings → Pages → Build and deployment**:

- Source: **Deploy from a branch**
- Branch: `main`, папка `/ (root)`

### Шаг 6. Запуск

**Actions → «Обновление расписания турниров» → Run workflow → Run workflow**.

Через 1–2 минуты данные появятся на сайте, ещё через 1–2 минуты обновится сам сайт.

## Источники данных

Скрипт умеет работать с двумя провайдерами и выбирает лучший доступный.

### 1. Sportradar Tennis API v3 — предпочтительный (нужен ключ)

| Данные | Запрос | Частота |
|---|---|---|
| Каталог турниров (уровень, пол, группа) | `/competitions.json` | раз в неделю (кэш) |
| Сезоны турниров | `/seasons.json` | раз в неделю (кэш) |
| Сетка матчей сезона + результаты | `/seasons/{id}/summaries.json` | идущие сезоны — каждый запуск, завершённые — навсегда |
| Мировой рейтинг | `/rankings.json` | раз в сутки |
| Фотографии игроков | `/tennis-images-t3/…/manifest.json` | раз в месяц (кэш) |

Каталог турниров **не зашит в код**: скрипт берёт из API поле `level`
(`grand_slam`, `atp_1000`, `wta_1000`) и группирует мужские и женские розыгрыши по `parent_id`.
Новый турнир в календаре появится сам.

### 2. Бесплатные источники — используются, если ключ Sportradar недоступен

| Источник | Что даёт | Ключ |
|---|---|---|
| [TennisMyLife](https://stats.tennismylife.org/tennis-match-database) | результаты ATP и WTA по годам (CSV, обновляется ежедневно): раунд, счёт по сетам, страны, посев, рейтинг на момент матча | не нужен |
| [Live Tennis API](https://livetennisapi.com) | **жеребьёвка будущих турниров с точным временем старта**, live-счёт по сетам, уровень турнира, рейтинг игроков | бесплатный, по почте |
| [SportScore](https://sportscore.com/developers/) | запасной источник live-матчей и фотографий игроков (CORS открыт) | не нужен |
| [Wikipedia / Wikimedia Commons](https://commons.wikimedia.org/) | фотографии игроков и текущий мировой рейтинг ATP/WTA (топ-20) | не нужен |

#### Live Tennis API — рекомендуемый бесплатный ключ

[livetennisapi.com/subscribe/free](https://livetennisapi.com/subscribe/free) — бесплатный тариф
**$0, без карты, ключ выдаётся сразу после подтверждения почты** (вида `twjp_…`).

| Тариф | Лимиты | Что доступно |
|---|---|---|
| **Free** | 30 запросов/мин, **100/сутки** | **рейтинг ATP и WTA** (список отсортирован по позиции), live-матчи и счёт, каталог турниров с уровнем, `/usage` |
| Basic ($9,99/мес) | 60/мин, 1000/сутки | + завершённые матчи, пошаговый протокол, архив 1968–2022 |
| Pro ($29,99/мес) | 300/мин, 10 000/сутки | + события матча, котировки, таблицы рейтинга |

Чтобы подключить, добавьте секрет `LIVETENNIS_API_KEY` (тот же путь: Settings → Secrets and
variables → Actions). Скрипт сам определит, что ключ есть.

**Что этот ключ реально даёт проекту (проверено прямыми запросами к API):**

- ✅ **мировой рейтинг ATP и WTA** — топ-60 в каждом туре вместо топ-20 из Википедии,
  с очками и страной;
- ✅ каталог турниров с уровнем (`grand_slam`, `atp_1000`, `wta_1000`), городом и страной;
- ❌ **матчей Большого шлема и Masters в бесплатной ленте нет** — проверено семью вариантами
  фильтров (с окном дат и без, с `tier` и без, с `draw`): в ленте только ITF, Challenger и
  Billie Jean King Cup. Матчи majors живут в платных тарифах;
- поэтому для полного live-счёта именно по Большому шлему и Masters нужен новый **бесплатный
  ключ Sportradar** (или тариф Basic у Live Tennis API за $9,99/мес).

Квота считается так, чтобы уложиться в 100 запросов в сутки: рейтинг — раз в 12 часов,
каталог турниров — раз в сутки, сводки матчей — с откатом до раза в 6 часов, если нашего
уровня в ленте нет.

Остальные источники закрывают остальное:

| Источник | Что даёт | Ключ |
|---|---|---|
| [TennisMyLife](https://stats.tennismylife.org/tennis-match-database) | результаты ATP и WTA по годам (CSV, ежедневно): раунд, счёт по сетам, страны, посев, рейтинг на момент матча | не нужен |
| [SportScore](https://sportscore.com/developers/) | запасной источник live-матчей и фотографий игроков (CORS открыт) | не нужен |
| [TennisExplorer](https://www.tennisexplorer.com/ranking/) | мировой рейтинг ATP и WTA (топ-50), сразу с кодом страны — если нет ключа Live Tennis API | не нужен |
| [Wikipedia / Wikimedia Commons](https://commons.wikimedia.org/) | фотографии игроков и турниров, календарь сезона, жеребьёвки, профили игроков, запасной рейтинг (топ-20) | не нужен |

Ограничения бесплатного режима:

- в TennisMyLife нет **точного времени** матча (только дата) — обратный отсчёт считается по дате;
- live-данные SportScore покрывают окно ~40 последних матчей;
- у части игроков нет фото — показывается заглушка с инициалами.

**Проверить, какой провайдер используется:** в логах workflow первая строка —
`Квота API: …` (Sportradar) или `TennisMyLife: результаты по годам…` (бесплатный).

### Как проверить, работает ли ключ Sportradar

В репозитории есть отдельный workflow **«Проверка ключа Sportradar»**
(`.github/workflows/check-api.yml`). Запустите его вручную (**Actions → Run workflow**) —
он покажет код ответа, тело и заголовки для основных эндпоинтов, а также контрольный запрос
без ключа. Если ключ отозван, все запросы вернут одинаковый `403 Authentication Error`.

Проверить можно и локально:

```bash
export SPORTRADAR_API_KEY=ваш_ключ
python scripts/fetch_tennis.py
```

Признаки проблем (выводит в лог и в интерфейсе сайта):

| Сообщение | Причина |
|---|---|
| `ключ недействителен или исчерпана месячная квота` | нужен новый ключ |
| `исчерпан месячный бюджет запросов` | скрипт сам остановился, чтобы не выжечь лимит; данные сохранятся |
| `Sportradar недоступен` | скрипт переключился на бесплатный провайдер |

### Расход лимита

Бесплатный тариф — **1000 запросов в месяц**. Скрипт кэширует всё, что меняется редко, поэтому укладывается в лимит:

| Что | Запросов в сутки |
|---|---|
| Идущие сезоны (2–3 турнира) | ~6–9 |
| Будущие сезоны (перепроверка раз в 2 дня) | ~3 |
| Рейтинг | 1 |
| **Итого** | **~12–15 в сутки, ~495 в месяц** |

Кэш лежит в каталоге `.cache/` и восстанавливается через `actions/cache`. Он не попадает в репозиторий.

#### Защита от перерасхода квоты

Скрипт **сам считает** потраченные запросы и хранит счётчик в кэше:

- `MONTHLY_REQUEST_BUDGET = 850` — мягкий порог (лимит Sportradar — 1000). Достигнут → скрипт перестаёт ходить в API и сохраняет последние рабочие данные;
- счётчик обнуляется в начале каждого календарного месяца;
- при ответе `401`/`403`/`429` скрипт **сразу прекращает** запросы, чтобы не выжигать остаток квоты, и пишет в лог причину.

> Важно: у Sportradar при исчерпании квоты возвращается **403**, а не 429. Старые версии скрипта это
> условие игнорировали и молча перезаписывали данные — из-за чего сайт выглядел работающим,
> хотя расписание не обновлялось с 16 сентября. Теперь такой случай явно падает в логах.

### Фотографии игроков

Фотографии берутся из **Wikipedia / Wikimedia Commons** — это бесплатный источник без API-ключа
и лимитов. Скрипт ищет статью игрока по имени и забирает превью (200 px).

Чтобы не ошибиться с однофамильцами (например, «Tommy Paul» — и теннисист, и футболист),
страница проверяется по короткому описанию: подходит только та, где в описании есть слово
«tennis». Если в основной статье нет фотографии, проверяется страница «… career statistics»,
и только затем — поиск по имени.

- Новых игроков ищем не более **60 за один запуск** (чтобы workflow не зависал);
- найденные фото кэшируются на **60 дней**;
- приоритет — у игроков, которые чаще всего встречаются в матчах;
- при наличии доступа к **Images API** Sportradar скрипт сначала пробует его (фото оттуда
  качественнее), а Wikipedia используется как запасной вариант;
- если фотографии нет — показывается круглая заглушка с инициалами.

Запросы к Wikipedia **не расходуют лимит Sportradar** и не учитываются в квоте API.

> Фотографии распространяются на условиях лицензий Wikimedia Commons. В подвале сайта стоит
> ссылка на источник.

### Разделение по годам

Год выбирается выпадающим списком в панели фильтров — на странице показывается только один
год, а не все сразу. По умолчанию открывается текущий календарный год, а если его нет —
ближайший доступный. Список скрыт на вкладке «Рейтинг».

### Сетка турнира

Внутри каждого турнира есть переключатель **Список ⇄ Сетка**. Сетка построена в стиле
профессиональных турнирных сайтов:

- раунды идут колонками слева направо: 1/8 → 1/4 → 1/2 → Финал;
- в каждом матче — оба игрока с посевом и счётом по сетам; победитель выделен;
- линии показывают, кто выходит в следующий раунд;
- сверху переключатель **ATP / WTA** и выбор начала сетки («С 1/8 финала», «Все раунды»);
- для ещё не сыгранных матчей участники показаны, а счёт пустой; как только матч
  завершается, данные обновляются и победитель автоматически встаёт в следующий раунд.

Связи между раундами восстанавливаются по победителям, поэтому сетка строится корректно
даже если источник не отдаёт готовую сетку.

### Частота обновления

- Workflow запускается **каждые 30 минут**, но сам скрипт решает, нужен ли запуск:
  - бесплатный провайдер обновляет данные раз в ~25 минут (эти запросы не тарифицируются);
  - Sportradar — не чаще раза в час, чтобы уложиться в лимит 1000 запросов в месяц;
  - если квота Sportradar исчерпана, скрипт переключается на бесплатный провайдер.
- Счёт и результаты обновляются по мере завершения матчей; страница сама перезапрашивает
  данные каждые 5 минут, если есть live- или предстоящие матчи.
- Частоту можно изменить в `.github/workflows/update-schedule.yml` (cron) и пороги
  обновления — вызовами `should_run("free", …)` и `should_run("sportradar", …)` в скриптах.

## Разработка

После изменения `app.js` или `styles.css` **увеличьте версию** в `index.html`
(`styles.css?v=N` и `app.js?v=N`) — иначе GitHub Pages ещё до 10 минут будет отдавать
старую версию файла из своего кэша.

Пересобрать демо-данные и фотографии к ним:

```bash
python tools/make_sample_data.py
python tools/make_sample_photos.py
```

```bash
python -m http.server 8000
# затем откройте http://localhost:8000
```

## Демо-данные
В каталоге `data/sample/` лежит демонстрационный набор (турниры, годы, рейтинг, фотографии).
Кнопка **«Посмотреть демо-данные»** на сайте показывает их без API-ключа.

Чтобы демо-данные стали основными (например, для проверки вёрстки), скопируйте их на место
боевых:

```bash
# Linux/macOS
cp data/sample/index.json data/index.json
cp data/sample/rankings.json data/rankings.json
cp data/sample/players.json data/players.json
cp -r data/sample/tournaments/. data/tournaments/

# Windows PowerShell
Copy-Item data\sample\index.json data\index.json
Copy-Item data\sample\rankings.json data\rankings.json
Copy-Item data\sample\players.json data\players.json
Copy-Item data\sample\tournaments\* data\tournaments\ -Recurse
```

Пересоздать демо-данные и их фотографии:

```bash
python tools/make_sample_data.py
python tools/make_sample_photos.py
```

В боевом режиме эти файлы перезаписываются скриптом автоматически.

## Решение проблем

### Сайт не обновляется

1. Проверьте вкладку **Actions** — есть ли ошибки в последних запусках
2. Убедитесь, что секрет `SPORTRADAR_API_KEY` добавлен
3. Запустите workflow вручную

### Ошибка 403 или 429

- **401/403** — ключ недействителен **или исчерпана месячная квота** (Sportradar отдаёт 403 и при
  исчерпании лимита, и при недействительном ключе). Проверьте ключ в
  [developer.sportradar.com](https://developer.sportradar.com/) и при необходимости выпустите новый.
  Если квота исчерпана, она обновится 1-го числа следующего месяца.
  **Пока ключа нет, сайт работает на бесплатных источниках** — данные обновятся автоматически.
- **429** — превышен лимит запросов. Уменьшите частоту в `.github/workflows/update-schedule.yml`:
  ```yaml
  - cron: '0 0,12 * * *'   # раз в 12 часов
  ```
  и поправьте `SCHEDULE_EVERY_HOURS` в `scripts/fetch_tennis.py` (значение `12`).
- Сбросить кэш: удалите каталог `.cache/` в репозитории Actions.

### Сайт показывает «Данные ещё не загружены»

Это значит, что workflow ещё ни разу не отработал успешно. Откройте **Actions** → последний запуск →
смотрите логи шага «Fetch tournament data». Типичная причина — 403 от API (см. выше).

Кнопка «Посмотреть демо-данные» на странице показывает, как всё выглядит с заполненными данными.

### Страница GitHub Pages не открывается

1. Settings → Pages — включена ли публикация
2. `index.html` должен лежать в корне репозитория
3. Подождите 5–10 минут

### Нет матчей на сайте

Это нормально вне турнирных периодов: расписание появляется за несколько дней до старта. Проверить API локально:

```bash
export SPORTRADAR_API_KEY=ваш_ключ      # Windows: $env:SPORTRADAR_API_KEY="ваш_ключ"
python scripts/fetch_tennis.py
```

### Нет фотографий игроков

Проверьте, что в вашем тарифе доступен **Images API** для тенниса. Без него календарь работает полностью — вместо фото показываются инициалы.
